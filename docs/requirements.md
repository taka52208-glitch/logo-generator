# ロゴ作成ジェネレーター 要件定義書

## 1. プロジェクト概要

### 成果目標
クラウドソーシング（クラウドワークス・ランサーズ等）のロゴコンペで、AI画像生成による高品質なロゴ案＋説得力のある提案文を無料で一括生成し、採用率を劇的に向上させるツール。

### 成功指標

**定量的指標:**
- 1案件あたり4パターンのロゴ案を10分以内に生成
- 提案文の生成時間を1分以内
- 月間コスト0円（無料APIのみ）
- コンペ採用率を10%以上に引き上げ

**定性的指標:**
- クライアントの業種・要望・ターゲット層に的確にマッチしたロゴ
- デザイン根拠を論理的に説明する提案文（配色理由・フォント選定理由・コンセプト）
- デザイン未経験者でも直感的に使える

### ターゲットユーザー
- クラウドソーシングのロゴコンペに応募するフリーランサー
- デザイン未経験だがロゴ案件で稼ぎたい人
- Midjourney等のAIツールを使っているが採用されない人

## 2. システム全体像

### 処理パイプライン

```
案件テキスト入力
    ↓
[Gemini API] 要件を構造化（業種・コンセプト・色・雰囲気・ターゲット抽出）
    ↓
[Gemini API] 構造化データ → ロゴ生成用英語プロンプト × 4パターン生成
    ↓
[Cloudflare FLUX.1] プロンプト × 4 → ロゴ画像 × 4 並列生成
    ↓
ユーザーがロゴを選択
    ↓
[Gemini API] 選択ロゴ＋要件 → 提案文生成（コンセプト・配色理由・フォント理由）
    ↓
[フロントエンド] ロゴ＋会社名テキスト → モックアップ生成（Canvas/CSS合成）
    ↓
提案パッケージ完成（ロゴDL + 提案文コピー）
```

### 機能一覧

| # | 機能名 | 説明 |
|---|--------|------|
| F-001 | 案件テキスト入力 | コンペの案件説明文を貼り付け |
| F-002 | 会社名入力 | ロゴに含める会社名・サービス名 |
| F-003 | 要件構造化 | AIが案件テキストから業種・コンセプト・色・雰囲気・ターゲットを自動抽出 |
| F-004 | プロンプト自動生成 | 構造化データから4パターンの英語プロンプトを自動生成 |
| F-005 | ロゴ一括生成 | FLUX.1 Schnellで4枚のロゴを並列生成 |
| F-006 | ロゴ選択 | 生成された4枚から好みのロゴを選択 |
| F-007 | 提案文自動生成 | 選択ロゴ＋要件からデザインコンセプト・配色理由・フォント理由を含む提案文を生成 |
| F-008 | モックアップ生成 | 名刺・看板・Webサイトでの使用イメージをCanvas/CSSで合成 |
| F-009 | ロゴダウンロード | PNG形式でロゴをダウンロード |
| F-010 | 提案文コピー | ワンクリックで提案文をクリップボードにコピー |

### ロール
- 認証なし（誰でもアクセス可能）

## 3. ページ詳細仕様

### P-001: 案件入力＋ロゴ生成ページ

- **ページID**: P-001
- **ルート**: `/`
- **目的**: 案件テキストからロゴを一括生成する
- **権限**: 誰でもアクセス可

**UI要素:**

| 要素 | 種類 | 説明 |
|------|------|------|
| 案件テキスト | テキストエリア | コンペの案件説明文を貼り付け（必須） |
| 会社名 | テキスト入力 | ロゴに含める会社名・サービス名（必須） |
| 生成ボタン | ボタン | ロゴ生成パイプラインを開始 |
| 要件分析結果 | 表示エリア | AIが抽出した業種・コンセプト・色・雰囲気・ターゲット（編集可能） |
| ロゴ一覧 | 画像グリッド（2×2） | 生成された4枚のロゴ画像 |
| 選択ボタン | 各ロゴ下 | 「この案で提案を作る」ボタン |

**処理フロー:**
1. ユーザーが案件テキスト＋会社名を入力
2. 「生成」ボタン押下
3. バックエンドへリクエスト送信
4. Gemini APIで要件を構造化→画面に表示（ユーザーは必要に応じて編集可）
5. Gemini APIで4パターンのプロンプト生成
6. Cloudflare FLUX.1で4枚並列生成
7. 生成完了後、4枚のロゴを画面に表示
8. ユーザーがロゴを選択→P-002へ遷移

**ローディング表示:**
- 「要件を分析中...」→「ロゴを生成中...（4枚）」のステップ表示
- 各ロゴは生成完了次第1枚ずつ表示

### P-002: 提案パッケージ生成ページ

- **ページID**: P-002
- **ルート**: `/proposal`
- **目的**: 選んだロゴに対し提案文＋モックアップを生成する
- **権限**: 誰でもアクセス可

**UI要素:**

| 要素 | 種類 | 説明 |
|------|------|------|
| 選択ロゴ | 画像表示 | P-001で選んだロゴ |
| 提案文 | テキスト表示 | AI生成の提案文（編集可能） |
| モックアップ | 画像グリッド | 名刺・看板・Webサイトイメージ（3種） |
| ロゴDLボタン | ボタン | PNG形式でダウンロード |
| 提案文コピーボタン | ボタン | クリップボードにコピー |
| モックアップDLボタン | ボタン | モックアップ画像をDL |
| 戻るボタン | ボタン | P-001に戻って別のロゴを選択 |

**提案文の構成:**
```
【デザインコンセプト】
（3〜5行のコンセプト説明）

【配色について】
（なぜこの色を選んだか、色の心理効果、業種との整合性）

【フォントについて】
（書体の特徴、ターゲット層との親和性）

【モチーフについて】
（ロゴのシンボル・形状の意味、企業理念との関連）

【展開イメージ】
（名刺、看板、Webサイト等での使用イメージの説明）
```

**モックアップ生成:**
- 名刺モックアップ: ロゴ＋会社名をCanvas上で名刺テンプレートに合成
- 看板モックアップ: 店舗看板テンプレートにロゴを配置
- Webサイトモックアップ: ヘッダー部分にロゴを配置したスクリーンショット風

**処理フロー:**
1. P-001から選択ロゴ＋要件データを受け取る
2. Gemini APIで提案文を自動生成→画面に表示
3. フロントエンドでモックアップ3種を自動合成→画面に表示
4. ユーザーは提案文を編集可能
5. 「提案文コピー」でクリップボードにコピー
6. 「ロゴDL」でPNGダウンロード

## 4. データ設計概要

MVPのためデータベースは使用しない。状態はフロントエンドのZustandストアで管理。

### フロントエンド状態（Zustand）

```typescript
interface LogoGeneratorState {
  // 入力
  briefText: string;           // 案件テキスト
  companyName: string;         // 会社名

  // 要件分析結果
  analysis: {
    industry: string;          // 業種
    concept: string;           // コンセプト
    colors: string[];          // 希望色
    mood: string;              // 雰囲気
    target: string;            // ターゲット層
    logoType: string;          // ロゴタイプ（シンボル/ロゴタイプ/コンビネーション）
  } | null;

  // 生成結果
  prompts: string[];           // 生成プロンプト4つ
  logos: string[];             // Base64ロゴ画像4枚
  selectedLogoIndex: number;   // 選択したロゴのインデックス

  // 提案パッケージ
  proposalText: string;        // 提案文
  mockups: {
    businessCard: string;      // 名刺モックアップ（Base64）
    signboard: string;         // 看板モックアップ（Base64）
    website: string;           // Webサイトモックアップ（Base64）
  } | null;

  // UI状態
  step: 'input' | 'analyzing' | 'generating' | 'selecting' | 'proposal';
}
```

### バックエンド API

| エンドポイント | メソッド | 説明 |
|---------------|---------|------|
| `GET /api/health` | GET | ヘルスチェック |
| `POST /api/analyze` | POST | 案件テキスト→要件構造化 |
| `POST /api/generate-prompts` | POST | 構造化要件→ロゴ生成プロンプト4つ |
| `POST /api/generate-logos` | POST | プロンプト→ロゴ画像4枚（並列生成） |
| `POST /api/generate-proposal` | POST | ロゴ＋要件→提案文生成 |

## 5. セキュリティ要件

### 全プロジェクト必須
- ヘルスチェックエンドポイント: `/api/health`
- グレースフルシャットダウン: SIGTERM対応、8秒タイムアウト
- HTTPS強制（本番）
- 入力値サニタイゼーション

### API関連
- Cloudflare APIトークン: サーバーサイドのみで使用、フロントエンドに露出させない
- Gemini APIキー: サーバーサイドのみで使用
- CORS設定: フロントエンドのオリジンのみ許可
- レート制限: 1IPあたり10リクエスト/分（悪用防止）

### 入力バリデーション
- 案件テキスト: 最大5,000文字
- 会社名: 最大100文字
- プロンプトインジェクション対策: ユーザー入力をLLMに渡す際のサニタイズ

## 8. Gemini プロンプト設計

### 8-1. 要件構造化プロンプト（POST /api/analyze）

```
あなたはロゴデザインの専門家です。
以下のクラウドソーシングのロゴコンペの案件説明文を分析し、
ロゴ制作に必要な要件を構造化してください。

案件説明文:
{brief_text}

会社名/サービス名:
{company_name}

以下のJSON形式で回答してください:
{
  "industry": "業種（例: IT、飲食、医療）",
  "concept": "コンセプト（50字以内）",
  "colors": ["推奨色1", "推奨色2"],
  "mood": "雰囲気（例: モダン、温かい、高級感）",
  "target": "ターゲット層",
  "logoType": "推奨ロゴタイプ（symbol/wordmark/combination）"
}

業種別の配色セオリー:
- IT・テクノロジー: 青、紺（知性、信頼性）
- 飲食・食品: 赤、オレンジ、黄（食欲増進）
- 医療・ヘルスケア: 青、緑、白（清潔感）
- 高級・ラグジュアリー: 黒、金、紺（洗練）
- 建設・不動産: 青、緑、茶（安定感）
- 美容・コスメ: ピンク、紫、金（華やかさ）
- 法律・士業: 紺、茶、金（格式）
- 環境・エコ: 緑（自然、持続可能性）
- 教育: 青、緑、オレンジ（知性、成長）
- スポーツ: 赤、青、黒（情熱、躍動感）

案件説明文に色の指定がある場合はそれを優先してください。
```

### 8-2. プロンプト生成（POST /api/generate-prompts）

```
あなたはAI画像生成のプロンプトエンジニアです。
以下の要件から、FLUX.1（Stable Diffusion系）用の
ロゴ生成プロンプトを4パターン作成してください。

要件:
{analysis_json}

ルール:
- 英語で出力
- 各プロンプトは異なるアプローチ（例: ミニマル、幾何学、有機的、レターマーク）
- 「文字・テキスト」はAIが苦手なので含めない（シンボルマークのみ）
- 白背景を指定（"on pure white background"）
- "minimal flat vector logo", "professional logo design", "scalable" を含める
- 色はカラーコードではなく色名で指定

以下のJSON配列で回答:
["プロンプト1", "プロンプト2", "プロンプト3", "プロンプト4"]
```

### 8-3. 提案文生成（POST /api/generate-proposal）

```
あなたはクラウドソーシングのロゴコンペで勝率の高い提案文を書くプロです。

以下の情報から、採用されやすい提案文を日本語で生成してください。

案件要件:
{analysis_json}

使用したプロンプト（デザイン方向性の参考）:
{selected_prompt}

提案文の構成（必ずこの構成で）:
【デザインコンセプト】
→ 3〜5行。企業理念・事業内容とロゴデザインの関連を論理的に説明

【配色について】
→ 色の心理効果と業種との整合性を説明

【フォントについて】
→ 推奨フォントの特徴とターゲット層との親和性を説明

【モチーフについて】
→ ロゴのシンボル・形状に込めた意味を説明

【展開イメージ】
→ 名刺・看板・Webサイト等での活用イメージを説明

注意:
- 「AIで生成しました」とは絶対に書かない
- プロのデザイナーとして自信を持った語調で
- クライアントの要望を深く理解していることが伝わる文章に
- 修正対応可能であることを最後に添える
```

## 9. ロゴ生成プロンプトのベストプラクティス

### 基本構造
```
[スタイル指定] + [ロゴの内容] + [色・形の指定] + [背景指定]
```

### 必須キーワード
- `minimal flat vector logo` / `simple geometric logo design`
- `professional logo design, scalable, high contrast`
- `centered composition`
- `on pure white background`

### 4パターンの方向性
1. **ミニマル幾何学**: シンプルな幾何学的形状の組み合わせ
2. **有機的・自然**: 曲線、自然モチーフ
3. **ネガティブスペース**: 余白を活かしたデザイン
4. **レターマーク風**: 頭文字をモチーフにした抽象デザイン

### 避けるべき表現
- `realistic` / `photorealistic`（写実的）
- `text` / `letters` / `typography`（AI は文字生成が苦手）
- `3D rendering`（フラットロゴには不要）
